## Scaffold a bot

`create-wapi-app` creates a ready-to-run bot (TypeScript or JavaScript) with a configured client, a `.env.example` and a text echo handler:

```bash
npm create wapi-app my-whatsapp-bot
```

The CLI asks for the directory name and the language. To skip the prompts, pass `--typescript` or `--javascript`, `--package-manager <npm|pnpm|yarn>`, and `--no-install` if you don't want it to install dependencies.

Then:

```bash
cd my-whatsapp-bot
cp .env.example .env   # fill in your token, ids, verify token and app secret
npm start              # builds and starts the webhook server on PORT (default 8080)
```

## Add wapi.js to an existing project

<Tabs>
  <Tab title="npm">
    ```bash
    npm install @wapijs/wapi.js@beta
    ```
  </Tab>
  <Tab title="pnpm">
    ```bash
    pnpm add @wapijs/wapi.js@beta
    ```
  </Tab>
  <Tab title="yarn">
    ```bash
    yarn add @wapijs/wapi.js@beta
    ```
  </Tab>
</Tabs>

<Note>
  The `@beta` tag installs 0.2. Without it, npm installs 0.1.x, which has a different API.
</Note>

The package has no runtime dependencies and ships ESM and CommonJS builds with type definitions:

```ts
import { Client } from "@wapijs/wapi.js"; // ESM
const { Client } = require("@wapijs/wapi.js"); // CommonJS
```

## Environment variables

Keep credentials out of your code. These are the names used throughout these docs:

```bash
WHATSAPP_API_ACCESS_TOKEN=
WHATSAPP_PHONE_NUMBER_ID=
WHATSAPP_BUSINESS_ACCOUNT_ID=
# Any string. Enter the same value as the verify token in the Meta dashboard.
WHATSAPP_WEBHOOK_VERIFY_TOKEN=
# App settings → Basic → App secret. Used to verify webhook signatures.
META_APP_SECRET=
```

<Note>Projects created with `create-wapi-app` name the token variable `WHATSAPP_API_ACCESS_TOKEN`. Any name works, as long as you pass the value to `accessToken`.</Note>
