WhatsApp sends incoming messages and status updates to a public HTTPS URL you register in your Meta app. This page covers the two secrets involved, getting a public URL during local development, and registering the URL with Meta.

## Verify token vs app secret

You need two different values. They are easy to mix up:

| | `webhook.verifyToken` | `webhook.appSecret` |
|---|---|---|
| What it is | Any string **you choose** | Meta's secret for your app |
| Where it comes from | You type it into the dashboard (*WhatsApp → Configuration → Verify token*) | *App settings → Basic → App secret* |
| What it does | Meta sends it once, when you click **Verify and save**. wapi.js answers the `GET` challenge only if it matches. | Meta signs every webhook `POST` with it (`X-Hub-Signature-256`). wapi.js checks the signature and rejects forged requests with `401`. |
| Required | Yes, to receive webhooks | No, but strongly recommended |

```ts
const client = new Client({
  accessToken: process.env.WHATSAPP_API_ACCESS_TOKEN!,
  phoneNumberId: process.env.WHATSAPP_PHONE_NUMBER_ID,
  webhook: {
    verifyToken: process.env.WHATSAPP_WEBHOOK_VERIFY_TOKEN!,
    appSecret: process.env.META_APP_SECRET,
    path: "/webhook", // default
    port: 8080, // default, built-in server only
  },
});

await client.webhook.listen();
```

<Note>In 0.1.x the verify token was called `webhookSecret`. It is now `webhook.verifyToken`; `appSecret` is new.</Note>

### Signature verification

When `appSecret` is set, wapi.js computes an HMAC-SHA256 of the **raw** request body and compares it with the `X-Hub-Signature-256` header in constant time:

- A missing or wrong signature gets `401` and no events are emitted.
- If the raw body is not available (for example, `express.json()` already parsed it), the request also gets `401`. wapi.js never accepts a payload it could not verify. See [Using your own server](/guide/building-your-application/using-your-own-server) to keep the raw body.
- Without `appSecret`, requests are accepted and wapi.js logs a single warning.

## Public URL for local development

Meta can only call a public HTTPS URL. While you develop locally, a tunnel forwards one to your machine.

<Note>Meta's dashboard sometimes rejects ngrok URLs as malicious. If that happens, use a Cloudflare Tunnel.</Note>

### Cloudflare Tunnel

1. [Install `cloudflared`](https://developers.cloudflare.com/cloudflare-one/connections/connect-apps/install-and-setup/installation).
2. Start the tunnel to your webhook port:

```bash
cloudflared tunnel --url http://localhost:8080
```

3. Copy the `https://<random>.trycloudflare.com` URL it prints:
  <Frame>
    <img src="/assets/configure-webhook/cloudlfare.png" />
  </Frame>

### ngrok

1. [Install ngrok](https://ngrok.com/download).
2. Start the tunnel:

```bash
ngrok http http://localhost:8080
```

3. Copy the `https://` forwarding URL:
  <Frame>
    <img src="/assets/configure-webhook/1.png" />
  </Frame>

<Tip>The built-in server listens on all interfaces by default. Behind a tunnel or reverse proxy you can bind it to localhost only with `client.webhook.listen({ host: "127.0.0.1" })`.</Tip>

Your callback URL is the tunnel URL plus the webhook path, for example `https://<random>.trycloudflare.com/webhook`.

## What wapi.js answers

| Request | Response |
|---|---|
| `GET` with `hub.mode=subscribe` and the right token | `200` + `hub.challenge` |
| `GET` with anything else | `403` |
| `POST` with a missing or wrong signature (`appSecret` set) | `401` |
| `POST` with invalid JSON | `400` |
| `POST` accepted | `200`, even if one change inside could not be decoded (it is reported through the `Error` event) so Meta does not re-deliver the whole batch |
